# 当前实验设计与评测口径

当前固定数据为 `medical-related-30-v1`：贫血、肾脏、甲状腺各十题，组间顺序与组内顺序由用户指定。题目、选项、答案从本地MedQA原文件逐字复制并校验指纹。三个题组均参与过先前71题实验，不能称为未见独立测试集。

## 连续性

这是知识复用型连续任务流：前题产生的证据、查询经验及过程记录可被后题检索；各题本身可独立解答。候选关系仅供评估，不预置到Agent输入或初始记忆。通过实际记忆ID、来源任务、回读和引用追踪验证复用，不以题目主题相似或模型自称使用作为唯一证据。

## 四条件

| 条件 | 角色输入表示 | 跨题记忆 |
| --- | --- | --- |
| text_off | 同字段可读文本 | 关闭 |
| structured_off | 紧凑JSON | 关闭 |
| text_on | 同字段可读文本 | 从空库开始在线积累 |
| structured_on | 紧凑JSON | 从空库开始在线积累 |

每条件30题、共120次任务执行。条件与条件之间串行，条件内题目串行。条件顺序由固定种子42生成并保存；题序不打乱。模型、角色提示、语料、工具、证据处理和预算一致。

各条件数据库独立，不复用旧71题库或其他条件记忆。当前设计在30题范围内持续积累，题组切换时不清空；不能描述为每组都独立冷启动。各组结果可按 `groups.json` 分解。

## 当前运行

API配置：`configs/medical-related-30-v1/compare-api.json`。生成服务使用deepseek-flash，参数与响应模型记录在manifest和usage中；检索、重排、embedding与SQLite在本地运行。

当前本机输出：`experiments/results/medical30-api-fourway-20261020-v2/`。原始日志、调用账本和数据库保留本地，默认不提交Git。`summary.md`、`group-summary.json`为自动汇总；未全量完成时必须保留“部分结果”标记。

v1在受限环境首个Planner请求连接失败，未取得响应usage，单独保留为失败记录；不得并入v2或当作零费用实验。v2在可联网宿主环境执行。旧实验均已归档，不作为当前版本的新结果。

## 分别测量

| 维度 | 指标与边界 |
| --- | --- |
| 答题 | 原始标准选项正确率、未答和运行失败；有答案不代表证据充分。 |
| 通信 | 角色请求/响应次数、字符、UTF-8字节、系统提示和控制字节；不是网络抓包包数。 |
| 模型成本 | API实际prompt/completion/total usage；缺失或未知用量明确记录。 |
| 状态 | 有负载的向量交换次数、float32负载字节、embedding耗时；非完整IPC总字节。 |
| 记忆 | 候选召回、展示、采纳、回读、策略执行、最终证据引用；来源有效不自动等于适用或正确。 |
| 重复工作 | 教材搜索、重排、来源回读、模型调用；减少检索次数不能直接称为减少模型推理。 |
| 效率 | 单题与整批耗时，额外编码/写入成本；续跑或共享资源影响另列。 |

当前四条件不单独隔离二进制状态编码的收益。若要作这项结论，需要对同一批向量单独比较JSON浮点数组与二进制的大小、编解码耗时、恢复误差和检索一致性。
