# MedQA 批量实验断点续跑（检查点 format=2）

适用于加入检查点功能后新建的 `run` 和 `compare` 实验。实现位于 [checkpoint.py](../LangChain/medqa/checkpoint.py) 和 [cli.py](../LangChain/medqa/cli.py)，不调用额外LLM。旧实验没有调用账本，不能自动迁移为可续跑实验。

## 使用

中断后，使用原命令类型和原目录恢复，不用重新填写题数或全部配置：

```bash
# 积累阶段的原目录；只有该目录实际创建后才能恢复
bash scripts/run_medqa.sh run --resume \
  --output experiments/results/medical30-single

# 四条件实验的原目录
bash scripts/run_medqa.sh compare --resume \
  --output experiments/results/medical30-api-fourway-20261020-v2
```

这些恢复命令仅适用于已经存在的对应检查点目录；当前30题API四条件运行见主README。恢复需要显式执行命令；未配置开机自动启动服务。CLI为Command-Line Interface，即命令行界面，适合脚本和批量实验；与实现质量、Agent自主性是不同概念。现有Flask/Vue界面仍连接旧通用工作流。

未指定 `--config` 时，从原检查点恢复参数；也可提供相同配置。显式覆盖参数仍会校验，不允许改变题目清单、题序、四条件顺序、预算、提示/运行时/记忆核心源码、模型设置、API端点指纹、数据或教材版本。API密钥不存入检查点，可以轮换密钥。仅模型别名相同不能保证服务端权重未变，正式实验仍需固定服务端版本并检查响应模型。

v5 format=1检查点不会被迁移或覆盖；升级后使用新目录。

结果目录有进程锁，同一时间只允许一个执行者；进程退出后系统释放锁。不要在运行时删除或替换目录、锁文件及数据库。

## 保存与恢复

| 中断位置 | 恢复动作 |
| --- | --- |
| 题目已完成 | 跳过，不重新调用模型，不重复计入Token |
| 题目未完成，部分响应已保存 | 重建该题本地流程，严格核对角色输入，直接重用已保存响应，从尚未完成处继续 |
| 结果与待写入记忆已保存，记忆尚未提交 | 只重放记忆写入，然后标记完成，不重新调用模型 |
| 记忆已提交但完成标志未保存 | 按来源/上下文幂等重写，不新增重复记忆条目 |
| JSONL/report导出中断 | 从SQLite账本重建；导出文件不是唯一依据 |
| 完整检索/处理视图已保存，下游状态未更新 | 读取已存结果重建状态，不重新搜索或重排 |
| 只读工具已计算，但结果未保存 | 标记未知计算窗口；在工具尝试预算内可重算，记录次数；不承诺物理exactly-once |
| 请求已登记但响应未保存 | 默认停止，不自动重发；该请求费用未知 |

每次请求前持久登记意图，收到响应后立即保存原始响应、usage和耗时，然后才解析。SQLite使用FULL同步；结果与待写入记忆在同一事务中保存。记忆写入采用待提交列表，未完成题目的知识不会提前对后续题目可见；评分结果和标准答案不进入待提交记忆。每个条件继续使用原记忆库，冻结记忆副本不会在续跑时覆盖。原库丢失会停止恢复。

已保存响应的重放仍计入原来的逻辑调用次数与Token，费用不重复相加。全局/条件Token预算从既有结果累计，题内已保存响应的Token也会在重放时恢复；题内调用额度不会因恢复清零。检索、来源回读、记忆预取与Evidence Processor完整视图先记操作意图再保存结果；已持久化完整结果按条件/题目/操作指纹直接复用，不再派发，不重复应用到逻辑状态。指纹覆盖语料、索引/重排器内容版本及检索参数。控制快照保存需求、查询、累计来源、进展、纠错记录和预算；重放必须与快照一致。已有完整模型响应也校验角色输入指纹，变化时保留检查点并停止。

每题期限包括本次运行时间和以前已落盘的模型/工具耗时；重放已有响应不额外发请求。断电期间不计时，未落盘的计算尾段和调度开销不能精确还原，因此不宣称跨进程严格累计墙钟期限。实际模型意图次数、已知Token和只读工具尝试均保留；未知窗口不获得免费重试额度。

## 响应未知的情况

远程API与本地磁盘不能原子提交。如果服务端已生成/计费，而机器在响应落盘前断电，仅靠本地文件无法还原该次用量。先核对服务端日志/账单；若接受重试的额外费用，可以显式执行：

```bash
bash scripts/run_medqa.sh run --resume \
  --output experiments/results/medical30-single --retry-unknown-calls
```

只有未完成题目的未落盘请求会重试；已经完成的错误题不会静默重跑。未知请求保留记录，重发也占用该题调用上限；记录的是请求意图次数，包含可能未真正到达服务端的请求。重复中断不能突破配置的max-calls上限。存在未知用量时，完成当前题后停止后续题目；已知Token只作下界，`token_usage_complete=false`，不计算Token节省率。已有完成结果仍含未知用量时，下一次恢复只修复导出并停止，不继续扩大费用。

## 产物与实验口径

- `checkpoint.sqlite3`：原配置、固定顺序、稳定trace、逐调用响应/usage、题目结果、待提交记忆；工具操作意图/完整结果、处理映射和控制快照；这是恢复依据。
- 各条件的 `*.sqlite3`：持续使用的记忆库和向量缓存，不能只复制checkpoint文件而遗漏这些文件。
- `*.jsonl`、`report.json`、`comparison.json`：可修复的导出视图；JSONL在普通运行中增量落盘，在恢复时重建。
- `recovery.json`：恢复次数、未知请求数、时延可比较标记。
- 逐题指标 `checkpoint_replayed_calls`、`checkpoint_request_attempts`、`checkpoint_unknown_calls`、`checkpoint_resumed`：分别记录重用响应、请求意图次数、未知请求和中断题恢复情况。

逻辑角色调用和原API用量可继续审计；恢复中重新执行的本地操作会影响缓存、耗时和IPC。发生过续跑的实验设置 `latency_comparison_valid=false`、时延节省率为null；不要用其IPC/耗时推导正常流程性能收益。已知响应完整且其余对照要求满足时，Token对比仍可进行；存在未知请求时不可进行。积累库必须全部题目和记忆提交完成、无未知请求，才允许作为冻结评估来源。

离线验证包括题间恢复、题内响应重放、真实进程直接退出、未知请求保护、参数/代码/模型变化、记忆待提交与幂等恢复、损坏导出修复、四条件顺序和预算延续。测试使用合成服务替身，未执行真实断电或真实模型费用实验；持久化还依赖操作系统、文件系统及存储设备正确实现同步写入。
