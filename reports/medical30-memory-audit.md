# 共享记忆指标与效果核对

结论：候选命中率高，但候选到实际使用的转化有限，且记忆没有替代新的调查工作。两轮四个记忆条件均未实现净Token节省。

## 新版结构化路径的转化过程

| 阶段 | 条数 |
|---|---:|
| 粗召回 | 224 |
| 进入Planner实际输入 | 73 |
| Planner选择并完成解析 | 21 |
| 其中证据记忆完成回读并交付 | 15 |

21条选中记忆由15条证据、3条策略、3条过程记录组成。最终8条来源引用分布在6道题。条数在每题内按记忆ID去重后跨题累计，不是唯一数据库记录数。

## 指标定义与尚未测量的项目

- 候选命中题比例：至少召回一条任意候选的题数/任务数，不是Recall@K。
- 检索Precision@K、Recall@K需要标注当前任务真正相关/可复用的历史记忆集合；目前没有这种标注，不能报告数值。
- Planner采纳率：选中条数/实际呈现条数，新版结构化为21/73=28.77%。
- 记忆来源引用题比例：引用到已回读记忆来源的题数/任务数，新版结构化为6/30=20%。不证明当前条件适用或节省了检索。
- 策略执行率：已执行策略条数/已交付策略条数，新版结构化为3/3=100%；涉及任务3/30，不能混用分母。
- 来源有效率：成功校验来源/实际回读来源；当前100%只说明来源可读和版本校验成功，不代表医学适用性100%。
- 净Token节省：1-开启记忆总Token/关闭记忆总Token，包含所有模型输入与输出。
- 还应单独标注错误复用、条件不适用、过期记忆以及需求覆盖率；现有选项准确率不能独立测出这些问题。

## 主要原因

1. 整题加全部选项用于Planner之前的粗召回；产生具体需求后没有再次按需求检索。缺口定向召回只在补查时执行，本轮补查为0。
2. 新版结构化224条候选中，86条是证据、71条策略、67条过程记录。三类竞争同一最多3条的模型输入配额。
3. 预览只保留摘要前160字符和前两条历史条件；全部224条候选都没有明确可机器使用的适用规则，标记为requires_current_task_review。
4. 记忆将历史病例条件与证据/策略混合编码，主题相关不保证解决当前具体需求；需要相关性标注验证，不能仅按相似度当成有效记忆。
5. 新版两个记忆条件的Investigator均30/30输出tool_plan，没有finish跳过调查。旧来源回读后仍然新检索，没有形成替代关系。
6. 无记忆条件也30/30答对，选项准确率没有上升空间。
7. 写入策略默认每题保存过程记录和查询策略，缺乏基于后续有用性的合并、淘汰和晋升。

新版结构化开记忆比关记忆多16,611个Token。按角色观察差额：Planner +7,685，Investigator +4,703，Reasoner +4,223。这个差额包含生成与检索变化，不是独立的因果成本分解。

## 统计口径问题

- 原report.memory_presented实际累计粗召回candidate_ids；新版结构化为224。真正进入Planner的条数应使用memory_funnel.presented，为73。
- 新版结构化raw delivered.evidence为16，但1条未解析候选因来源ID与新检索结果重合而被标记交付；严格交付应为15。原报告来源引用率8/16=50%，严格应为8/15=53.33%。
- reused_memory_ids按来源ID归因，不能证明使用的是记忆原先保存的同一引句。新版结构化8条来源引用中，5条逐字等于存储引句，7条有引句包含关系；这些都不是语义适用性或因果收益的证明。
- 原始实验文件保持不变，此文档和JSON记录核对后的定义与差异，不进行新的API调用。

## 改进优先级

先统一统计分母，再做少量“任务—可复用记忆”人工标注；按知识需求组织召回与摘要；按类型和需要选择记忆；以需求覆盖决定新检索目标；最后在真正需要前序产物的连续任务中验证净Token收益。不能靠降低阈值、强制引用或强制跳过检索制造复用率。
